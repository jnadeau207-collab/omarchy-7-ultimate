# Fabric QML transport

`shell/services/FabricClient.qml` is the shell-owned adapter for the per-user Agent Fabric Unix socket. `shell/services/FabricTransport.js` owns framing, validation, correlation, deadlines, event buffering, and reconnect state independently of Quickshell so the complete state machine can run against a deterministic fake socket.

The running shell instantiates one private-by-scope `fabricClient`, but it ships inactive with an empty public-method allowlist and is not attached to the injected `shell` object. This establishes the integration seam without creating a standing capability grant, exposing an IPC route, converting a production provider, or making daemon availability a shell-start requirement. Activating the socket, exposing it to a consumer, granting methods, and removing the character-set restriction are separate owned changes.

## Connection contract

The adapter connects to `$XDG_RUNTIME_DIR/omarchy/fabric.sock` and immediately sends the required `hello` request for `omarchy.fabric.rpc/v0`, version 0. The client becomes ready only after the correlated hello result repeats the protocol, selected version, client label, and a non-empty connection ID. An incompatible envelope protocol, incompatible selected version, the daemon's `rpc.incompatible-version` response, or a response outside the adapter's character-set subset closes the socket and blocks automatic reconnect until a disconnected `retryConnection()` or an explicit deactivate/reactivate cycle. `retryConnection()` returns false without changing state while a connection is ready, open, connecting, or still awaiting expected close feedback. Other disconnects use bounded exponential backoff from 250 milliseconds through 8 seconds and negotiate a new hello session.

Fabric RPC v0 is a UTF-8 protocol, but this provisional Quickshell adapter deliberately implements only a semantic and wire-level US-ASCII subset. Every raw chunk, JSON object key, and JSON string value must contain characters U+0000 through U+007F; raw Unicode, decoder replacement characters, and escaped semantic Unicode all fail closed as `rpc.unsupported-character-set`. A request containing Unicode is rejected before any write. This restriction makes arbitrary `SplitParser` chunking byte-safe because every accepted byte maps to exactly one `QString` character. It also means the adapter must not be activated for any consumer whose requests, results, errors, or events can contain Unicode. The dormant shell instance is not a general UTF-8 Fabric client.

Within that subset, frames are newline-delimited JSON with a 65,536-byte limit excluding the newline. The JavaScript reader accepts fragmented and coalesced chunks, rejects ambiguous duplicate object keys, bounds nesting, validates exact result/error/event envelopes, and rejects unknown fields. Incoming event sequence integers must remain JavaScript-safe. A malformed envelope, oversized or truncated frame, pre-handshake event, or event-buffer overflow fails the connection closed. The client never guesses past a protocol error.

Requests have correlated client-generated IDs, a five-second default deadline, and a default maximum of 64 pending requests. The default event queue holds at most 256 validated events. A caller consumes queued events through `takeEvent()` and uses the durable event cursor to replay after an overflow or reconnect. Timeout, disconnect, stop, and local cancellation all remove pending correlation state and return an explicit structured error. No request is automatically replayed because the client cannot infer whether a consequential operation changed the machine.

Every instance has an exact `allowedMethods` list. `hello` is internal; a caller cannot replace it. Method syntax and allowlist membership are checked before connectivity, so a public request not named in the list is always rejected locally as `client.method-denied`; an allowed method reports `daemon.disconnected` when the handshake is unavailable. The shell's initial instance allows no public method. This allowlist is a consumer-safety boundary, not an authorization boundary: same-process QML can create its own socket, so the daemon Trust Plane must still authorize the endpoint-bound principal for every consequential method.

## Intentional limits

- `FabricClient.cancel(requestId)` cancels only local waiting and reports remote change state as unknown. A long-running consequential operation must call its typed operation cancellation method and then reconcile through the operation ledger.
- Reconnect restores only the socket and hello session. Subscription owners must reconnect, resubscribe with their durable cursor, and handle cursor expiry explicitly.
- Quickshell 0.3.1 exposes `Socket` reads to QML as independently decoded `QString` chunks, not raw `QByteArray`, and exposes `write()` as `void` with no writable high-water signal. Its [v0.3.1 `SplitParser` implementation](https://github.com/quickshell-mirror/quickshell/blob/v0.3.1/src/io/datastream.cpp) constructs a separate `QString` for each underlying read when the marker is empty; with a newline marker it preserves bytes but can buffer an unbounded frame before QML sees it. The current adapter therefore accepts US-ASCII only, caps in-flight writes, flushes every bounded frame, and relies on deadlines for an unacknowledged write. General UTF-8 activation requires a raw-byte parser that incrementally enforces the frame limit plus observable write backpressure; this is an explicit blocker, not deferred proof.
- Explicit stop and protocol-triggered close record expected asynchronous socket feedback. That feedback and any duplicate close signal are consumed without replacing the intentional disabled state or the original protocol diagnostic with a synthetic `daemon.disconnected` error.
- The current Arch Quickshell package embeds `quickshell-coreplugin` under the executable's `qrc:/qt/qml` resources instead of installing a shared QML plugin. `qmllint` can validate the installed 0.3.1 type metadata, but an external `qmltestrunner` cannot instantiate the type. The conditional QML smoke fixture runs where a shared plugin exists; on this reference package, live component loading must be verified as part of the one permitted shell process rather than by launching a second Quickshell.
- Configuration limits are fixed when the JavaScript engine is created. Changing pending, event, timeout, or backoff properties requires recreating the component; only `allowedMethods` updates live.
- The transport carries protocol messages only. It does not hold credentials, approvals, grants, provider implementations, process execution, undo authority, or the privileged system executor.

## Verification

`test/shell.d/fabric-qml-transport-test.sh` uses a hermetic fake socket and clock. It covers fragmented and coalesced ASCII newline JSON, out-of-order correlated replies, structured remote errors, own-key change-state validation, unsolicited events, reconnect backoff and reset, ready-state retry rejection, expected asynchronous close feedback, strict version and character-set blocking, exact and oversized frames, pending and event bounds, timeout and cancellation cleanup, late replies, duplicate keys, malformed envelopes, and the authority-free shell integration. Unicode request values, raw Unicode responses, decoder replacement from a split multibyte sequence, and escaped semantic Unicode all have deterministic rejection coverage. The test also checks that the QML adapter uses Quickshell's Unix `Socket`, arbitrary-chunk `SplitParser`, explicit `write()` plus `flush()`, and an inactive empty-allowlist production instance.
